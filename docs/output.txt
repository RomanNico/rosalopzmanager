Planteamiento del Problema 
¿De qué manera la implementación de un sistema web automatizado puede mejorar la eficiencia operativa de la fábrica de calzado Bufalo R.P.?
La fábrica de calzado Bufalo R.P., en Bogotá D.C., gestiona manualmente sus nóminas, tareas e inventarios con libretas y vales de cobro, lo que genera errores, duplicidad de registros y dificulta el acceso a información clave. Esta falta de digitalización provoca cálculos salariales incorrectos, retrasos en inventarios y desorganización en la asignación de tareas, afectando la toma de decisiones y la eficiencia operativa.
Para solucionar esto, se propone ROSALOPZManager, una plataforma web basada en HTML, CSS, JavaScript y PostgreSQL, que automatizará estos procesos, reducirá errores y optimizará la gestión. Esto beneficiará tanto a administradores como empleados, mejorando la precisión, transparencia y productividad de la empresa.
Justificación 
La digitalización de la gestión de nóminas, tareas e inventarios en Bufalo R.P. es clave para mejorar la eficiencia, reducir errores y optimizar la administración. Actualmente, el manejo manual genera retrasos en sueldos, desorganización y falta de control en inventarios, afectando la productividad y toma de decisiones.
La implementación de ROSALOPZManager , una plataforma web desarrollada en HTML, CSS, JavaScript y PostgreSQL, automatizará estos procesos, mejorando la precisión y optimizando la administración. Este sistema permitirá un acceso rápido a la información, garantizará pagos puntuales, facilitará el control de inventarios y optimizará la asignación de tareas. Además, generará reportes en tiempo real para una mejor toma de decisiones, reduciendo la carga administrativa y fortaleciendo el crecimiento de la empresa.
Objetivos 
Objetivo General
Desarrollar un sistema web para digitalizar nóminas, tareas e inventarios en la fábrica de calzado Bufalo R.P., con el propósito de mejorar la eficiencia operativa, minimizando errores y facilitar la toma de decisiones informadas.
Objetivos Específicos 
Implementar un módulo de nómina automatizado que permita calcular sueldos, registrar pagos y almacenar la información en una base de datos PostgreSQL, eliminando errores y agilizando el proceso de pago a empleados.
Desarrollar un sistema de gestión de inventarios que registre el ingreso y salida de materiales, genere alertas de stock y facilite el control en tiempo real, optimizando la planificación de producción.
Crear un módulo de asignación y seguimiento de tareas que permita a los jefes distribuir actividades entre los empleados, registrar su cumplimiento y generar reportes automáticos para mejorar la supervisión y productividad.
Marco Teórico 
Introducción 
El marco teórico de esta investigación busca explicar por qué es importante usar la tecnología en la gestión diaria de empresas manufactureras, como la fábrica de calzado Bufalo R.P. Se estudiarán ideas sobre automatización, sistemas de información y manejo de recursos. Revisar lo que ya se sabe sobre este tema nos ayudará a entender cómo la tecnología puede hacer que las empresas trabajen de manera más eficiente y cometan menos errores.
Digitalización y Automatización en la Gestión Empresarial
La digitalización y la automatización de procesos son fundamentales para optimizar las operaciones empresariales en la era de la Industria 4.0. La digitalización implica la conversión de procesos analógicos en digitales, lo que permite una mayor eficiencia, velocidad y calidad en la producción. Esta transformación facilita la recopilación y análisis de datos en tiempo real, mejorando la toma de decisiones estratégicas y la adaptabilidad al mercado. (Geprom, 2024)
Por otro lado, la automatización de procesos consiste en el uso de tecnologías para ejecutar tareas repetitivas sin intervención humana, lo que incrementa la productividad y reduce los costos operativos. Al implementar sistemas automatizados, las empresas pueden optimizar la asignación de recursos, garantizar la continuidad operativa y mejorar la calidad de sus productos o servicios. (SAP, Automatización de procesos: la clave para la eficiencia, 2024)
La integración de estas tecnologías no solo mejora la eficiencia operativa, sino que también aumenta la competitividad empresarial al permitir una respuesta más ágil a las demandas del mercado. Además, la digitalización y la automatización contribuyen a la sostenibilidad al reducir el consumo de recursos y minimizar errores humanos.
Sistemas de Planificación de Recursos Empresariales
Los sistemas de información empresarial, especialmente los sistemas de planificación de recursos empresariales (ERP), desempeñan un papel crucial en la gestión eficiente de diversas áreas dentro de las organizaciones manufactureras. Estos sistemas integran funciones esenciales como finanzas, recursos humanos, producción y gestión de inventarios, proporcionando una visión unificada y en tiempo real de las operaciones empresariales. (SAP, ¿Qué es ERP?, 2024)
Además, los sistemas ERP facilitan la gestión de recursos humanos al automatizar procesos como la nómina, el seguimiento de asistencia y la evaluación del desempeño. Esto no solo reduce errores humanos, sino que también libera tiempo para que el personal de recursos humanos se enfoque en actividades estratégicas, mejorando la productividad general de la organización. (Velneo, 2025)
Conceptos Claves 
Base de datos
Definición
Una base de datos será el corazón de tu sistema web. Es el lugar donde se guardará toda la información pertinente, tales como:
Información de los trabajadores: Nombres, documentos, puestos, sueldos, trayectoria laboral, entre otros.
Información del sueldo: Cálculos de sueldos, deducciones, bonificaciones, pagos efectuados, entre otros.
Tareas cumplidas: Descripciones de las tareas, personal asignado, fechas de comienzo y término, entre otros.
Inventarios: Productos en inventario, proveedores, volúmenes, costos, entre otros.
 Clasificaciones de las bases de datos:
Relacionales: Son las más habituales y emplean tablas para ordenar los datos. Casos prácticos: MySQL, PostgreSQL, SQL Server.
No relacionales: Son más adaptables y escalables, perfectos para manejar grandes cantidades de información. Algunas alternativas: MongoDB, Cassandra.
 Conceptos para tener en cuenta al seleccionar una base de datos:
Dimensiones de la base de datos: ¿Qué cantidad de información se guardará?
Tipo de datos: ¿Qué clase de datos se guardará (numéricos, escritos, imágenes)?
Velocidad de acceso: ¿Cuál es la rapidez requerida para obtener los datos?
Escalabilidad: ¿Será posible expandir la base de datos junto al negocio?
Seguridad: ¿Qué acciones de seguridad se necesitan para salvaguardar la información?
(concepto.de, 2024)
Aplicación web
Definición
Una aplicación web es una herramienta esencial para tu proyecto. Es mediante esta que los usuarios (trabajadores, gestores) se relacionarán con la base de datos.
 Características de la aplicación en línea:
Manejo de la nómina: Estimación automática de salarios, creación de informes, abonos electrónicos.
Registro de tareas: Asignación de responsabilidades, monitoreo del avance, elaboración de reportes.
Control de inventarios: Documentación de las entradas y salidas de mercancías, creación de alertas de escasez de inventario.
Acceso a datos personales: Los trabajadores tendrán la posibilidad de acceder a su información personal y laboral.
Informaciones y documentos: Creación de informes a medida para la toma de decisiones.
(amazon.com, 2024)
El Calzado
Definición
Esta industria, una de las más antiguas y globalizadas, abarca el diseño, producción, distribución y venta de variados modelos de calzado destinados a distintos públicos (hombres, mujeres, niños, atletas, entre otros). La demanda se ve motivada por elementos como la moda, el modo de vida, la funcionalidad y la comodidad.
 Clases de Zapatos:
Zapatos deportivos: Concentrados en el desempeño, la comodidad y el respaldo para actividades físicas particulares como correr, entrenar o practicar deportes.
Calzado de gala: Principalmente empleado en contextos profesionales o ceremoniales, donde la elegancia y la estética son esenciales.
Calzado casual: Creado para el uso cotidiano, donde la comodidad es el elemento principal.
Calzado especializado: Incorpora zapatos laborales con propiedades de seguridad.
 Procesos de Producción de Calzado:
Diseño: Inicia con el diseño y la creación de un prototipo, a menudo utilizando software CAD para planificar las dimensiones y características del calzado.
Corte y preparación: El material, ya sea cuero, tela u otros, se corta en las formas y patrones necesarios. En esta fase, las máquinas y trabajadores especializados preparan las piezas que conformarán el zapato.
Montaje y acabado: Las partes cortadas (como la suela, el empeine y los forros) se ensamblan y cosen. La automatización de esta parte del proceso ha permitido mejorar la eficiencia y la precisión en la producción.
Control de calidad: Cada producto pasa por una fase de control de calidad para asegurarse de que cumple con los estándares de fabricación y diseño.
(Orús, 2024)
HTML (Hypertext Markup Language)
 Definición
HTML se define como el lenguaje estándar empleado para la creación y organización del contenido de una página web. Actúa como el fundamento de toda aplicación en línea, suministrando la estructura y el contenido (texto, imágenes, vídeos, formularios, etc.) que el navegador web procesa y presenta a los usuarios.
 Características fundamentales:
Estructura del documento: HTML estructura el contenido en una jerarquía de componentes (etiquetas), en la que cada componente cumple una función determinada, tal como <header>, <section>, <article>, <footer>, entre otros. Esto facilita la organización de las páginas de forma lógica y semántica.
Semántica: Gracias a la implementación de HTML5, se han incorporado nuevas etiquetas semánticas que optimizan la accesibilidad y la organización de los documentos, tales como <article>, <aside>, <figure>, <nav>, entre otros.
Multimedia: HTML5 también soporta componentes multimedia como video (<video>) y audio (<audio>), lo que facilita la incorporación directa de estos recursos sin la necesidad de añadir complementos extra como Flash.
Formularios: Los formularios en HTML (<form>) facilitan la interacción del usuario con la aplicación en línea, recogiendo información tales como nombre, email, etc.
(MDN, HTML: Lenguaje de etiquetas de hipertexto, 2024)
CSS (Cascading Style Sheets)
 Definición
CSS es un lenguaje de programación empleado para establecer el estilo visual de los documentos HTML. Facilita la gestión de la presentación y el diseño de los sitios web, considerando elementos como los colores, las fuentes, los márgenes, los espaciados y la disposición de componentes.
 Características fundamentales:
Diseño: CSS se emplea para estructurar la manera en que se exhibirán los componentes HTML en la pantalla. Características como display, flexbox y grid facilitan la creación de layouts complejos y responsivos que se ajustan a distintos dispositivos.
Design Responsivo: CSS facilita la adaptación de las páginas a diversos tamaños de pantalla, garantizando una experiencia de usuario excelente tanto en ordenadores de escritorio como en aparatos móviles. Es vital para un sistema web que será empleado por diversas personas, en diferentes dispositivos, en el interior de la fábrica.
Estilos visuales: CSS establece el estilo visual de los componentes, tales como los colores (color, color de fondos), las fuentes (font-family, font-size), los bordes (border), entre otros, proporcionando uniformidad a la interfaz de usuario.
Animaciones y Transiciones: CSS facilita la incorporación de transiciones y animaciones que potencian la experiencia del usuario al interactuar con la página.
(MDN, CSS, 2024)
JavaScript
 Definición
JavaScript es un lenguaje de codificación que opera en el navegador web y facilita la incorporación de interactividad y dinamismo en las páginas HTML. Además de HTML y CSS, JavaScript es una de las tecnologías fundamentales en el desarrollo web, facilitando la creación de aplicaciones web dinámicas y de respuesta.
 Características fundamentales
Manejo del DOM (Modelo de Elementos Documentales): JavaScript tiene la capacidad de acceder y modificar los componentes del documento HTML en tiempo real, facilitando la creación de interfaces dinámicas, como la actualización de la lista de existencias sin tener que recargar la página.
Verificación de Formularios: Previo a enviar la información al servidor, JavaScript tiene la capacidad de verificar los campos del formulario (como comprobar que el email es válido) con el objetivo de optimizar la experiencia del usuario y prevenir fallos.
AJAX: Mediante AJAX (Asynchronous JavaScript and XML), JavaScript facilita el envío y recepción de datos del servidor de forma asíncrona, lo que potencia la rapidez y fluidez de las aplicaciones web. Por ejemplo, es posible actualizar el inventario o revisar las nóminas sin que la página se recargara completamente.
Frameworks y Librerías: JavaScript cuenta con numerosas librerías y frameworks famosos como React, Vue.js, Angular, jQuery, entre otros, que simplifican la creación de aplicaciones web actuales y escalables.
Eventos e Interactividad: JavaScript tiene la capacidad de identificar sucesos (tales como pulsaciones de botones, pulsaciones de teclas, modificaciones en los campos de formularios) y responder a estos, lo cual es esencial para desarrollar interfaces interactivas.
(Slotnisky, 2022)
Sistema de Gestión Digitalizado
 Definición 
Un sistema de gestión digitalizado es una plataforma tecnológica que integra procesos y funciones con el fin de mejorar la eficiencia operativa dentro de una organización. Este sistema permite centralizar la información y optimizar la toma de decisiones al facilitar el acceso a datos en tiempo real, alineando áreas administrativas y operativas .
 Características
Automatización: Los procesos se realizan automáticamente, reduciendo la intervención manual y los errores.
Centralización de datos: Se recopilan y almacenan datos en un solo lugar, facilitando su acceso y gestión.
Acceso remoto: Permite a los usuarios acceder a la plataforma desde cualquier lugar, aumentando la flexibilidad.
Seguridad: Implementa medidas de seguridad para proteger la información sensible.
Escalabilidad: Capacidad de adaptarse a las necesidades cambiantes de la organización a medida que crece .
 Beneficios
Mejora la eficiencia operativa al optimizar procesos.
Reduce errores en la gestión de datos.
Aumenta la productividad al liberar tiempo y recursos.
Mejora la toma de decisiones gracias a la disponibilidad de información actualizada .
(Zirquit, 2022)
Gestión de Nóminas
 Definición 
La gestión de nóminas es el proceso de cálculo y pago de sueldos y beneficios a los empleados, asegurando que se cumplan todas las normativas laborales y fiscales .
 Características
Cálculo de salarios: Determinación precisa de las remuneraciones basadas en horas trabajadas y tasas acordadas.
Deducciones: Cálculo de impuestos y contribuciones a la seguridad social.
Beneficios: Inclusión de bonificaciones y otros incentivos.
Pagos: Procesamiento oportuno de los pagos a los empleados .
 Beneficios
Garantiza la precisión y puntualidad en los pagos, lo que fortalece la confianza del empleado.
Reduce errores en los cálculos de nómina, minimizando disputas laborales.
Mejora la satisfacción del empleado al garantizar que los beneficios se calculen y distribuyan correctamente .
(Personio, 2022)
Gestión de Inventarios
 Definición 
La gestión de inventarios se refiere al control y administración de materiales y productos en una organización, garantizando que haya un equilibrio entre la oferta y la demanda .
 Características
Registro de entradas y salidas: Seguimiento preciso de los movimientos de inventario.
Control de stock: Monitoreo de los niveles de existencias para evitar desabastecimientos o excesos.
Seguimiento de ubicaciones: Identificación de la ubicación de cada producto en el almacén.
Gestión de pedidos: Coordinación de las solicitudes de reabastecimiento .
 Beneficios
Reduce el riesgo de desabastecimiento o exceso de stock, lo que puede afectar la producción.
Mejora la planificación de la producción, asegurando que los materiales estén disponibles cuando se necesiten.
Reduce costos relacionados con la gestión de inventarios y mejora la eficiencia operativa .
(IBM, 2024)
Vigilancia Tecnológica
Comparación entre ROSALOPZManager y Softland
ROSALOPZManager es un sistema en desarrollo destinado a mejorar la gestión de nóminas, tareas e inventarios en la fábrica de calzado Bufalo R.P. En contraste, Softland es un software ERP (Sistemas de Planificación de Recursos Empresariales) ampliamente utilizado en diversas empresas de Colombia, ofreciendo soluciones integrales para la gestión empresarial.
Enfoque y Adaptabilidad:
ROSALOPZManager se diseñará específicamente para las necesidades de Bufalo R.P., priorizando la eficiencia y la usabilidad para el personal de la fábrica. Su objetivo es simplificar procesos manuales, integrando herramientas digitales que se adapten a la cultura y operación de la empresa.
Softland, aunque es un sistema robusto, está diseñado para una amplia gama de industrias. Esto puede resultar en una menor adaptabilidad a las necesidades específicas de una empresa más pequeña como Bufalo R.P. Su enfoque integral a menudo requiere personalización, lo que puede ser un desafío para empresas con menos recursos técnicos.
Tecnología y Escalabilidad:
ROSALOPZManager se desarrollará utilizando tecnologías modernas como HTML, CSS, JavaScript y PostgreSQL, lo que facilitará su implementación y escalabilidad a medida que la empresa crezca. La digitalización de procesos clave permitirá una rápida adaptación a los cambios del mercado y una mejora continua.
Softland emplea tecnologías consolidadas y robustas, ofreciendo una variedad de funcionalidades. Sin embargo, su complejidad técnica puede limitar su escalabilidad para empresas que no tienen el mismo nivel de soporte técnico.
Costos y Accesibilidad:
ROSALOPZManager pretende ser una solución más accesible en términos de costos. Al ser desarrollado internamente y adaptado a las necesidades de Bufalo R.P., se busca minimizar los gastos relacionados con licencias y mantenimiento que suelen estar asociados con software comercial como Softland.
Softland, al ser un software ERP establecido, puede conllevar costos elevados en términos de licencias, implementación y formación del personal. Esto puede ser un obstáculo para empresas más pequeñas que buscan optimizar sus operaciones sin incurrir en altos gastos.
Facilidad de Uso:
ROSALOPZManager se centrará en ofrecer una interfaz intuitiva, facilitando su uso por parte de todos los empleados, independientemente de su nivel de familiaridad con la tecnología. Esto contribuirá a una rápida adopción del sistema dentro de la empresa.
Softland puede ser más complicado de utilizar debido a su amplia gama de funcionalidades. La capacitación necesaria para los empleados puede ser extensa, lo que puede ralentizar el proceso de implementación.
Soporte y Actualizaciones:
ROSALOPZManager tendrá la ventaja de contar con soporte interno directo, lo que permitirá ajustes rápidos y actualizaciones basadas en el feedback de los usuarios. Esta cercanía con los empleados puede mejorar la experiencia general del sistema.
Softland ofrece un soporte técnico profesional, pero la dependencia de un proveedor externo puede resultar en tiempos de respuesta más lentos para solucionar problemas o implementar cambios.
ROSALOPZManager busca satisfacer las necesidades específicas de Bufalo R.P. con un enfoque adaptado y costos reducidos, mientras que Softland proporciona una solución ERP más generalizada que, aunque completa, puede ser excesiva y menos flexible para una empresa más pequeña. Al final, la elección entre ambos dependerá de las necesidades específicas y los recursos disponibles de cada empresa.

Alcance
El presente proyecto tiene como objetivo el desarrollo de una plataforma digital llamada ROSALOPZManager, orientada a optimizar la gestión administrativa en la fábrica de calzado Bufalo R.P. Inicialmente, el sistema estará enfocado en cubrir procesos clave como la gestión de nómina, control de inventarios y asignación de tareas dentro de esta empresa específica. No obstante, se proyecta que, tras su implementación y validación local, la plataforma pueda escalarse a otras fábricas del sector calzado, e incluso adaptarse a las necesidades de empresas manufactureras de diferentes áreas productivas, ajustando sus funcionalidades a cada contexto.
Hipótesis
La implementación de una plataforma digital de gestión como ROSALOPZManager en la fábrica Bufalo R.P. mejorará significativamente la eficiencia administrativa, reduciendo errores en nómina, optimizando el control de inventarios y mejorando la organización de las tareas, en comparación con los procesos manuales actuales.

Nivel de satisfacción con los procesos actuales.

Escalas de Medición 
Se emplean escalas ordinales (como la de Likert de 1 a 5) para evaluar percepciones y niveles de eficiencia, así como opciones categóricas cerradas para medir experiencia laboral, frecuencia de errores y disposición a usar nuevas herramientas. Ejemplos:
Escala de Likert (1 a 5) para medir eficiencia o satisfacción.
Categorías como “Nunca / Rara vez / A veces / Frecuentemente / Siempre”.
Respuestas binarias tipo “Sí / No”.
Validez y Confiabilidad 
Para garantizar la claridad y relevancia del cuestionario, se realizará una revisión interna cuidadosa, enfocada en asegurar que cada pregunta esté alineada con los objetivos del proyecto. Además, se planea aplicar el cuestionario piloto a un pequeño grupo de trabajadores, con el fin de identificar posibles dificultades de interpretación y ajustar el instrumento antes de su aplicación definitiva. Este proceso busca fortalecer la consistencia del instrumento.
Codificación y Análisis
Las respuestas serán codificadas numéricamente y analizadas con herramientas como Microsoft Excel, permitiendo realizar un análisis descriptivo mediante frecuencias, medias, modas y desviaciones estándar. Los resultados del análisis demuestran que los problemas recurrentes en gestión de nóminas, asignación de tareas y control de inventarios en Bufalo R.P. están directamente relacionados con la dependencia de procesos manuales y la falta de un sistema integrado.
ROSALOPZManager se presenta como la solución óptima porque:

Optimizará el control de inventarios con alertas automatizadas que prevendrán retrasos por falta de materiales.
Centralizará la información en una plataforma accesible, mejorando la transparencia y la toma de decisiones.
Se adaptará a las necesidades específicas de la fábrica, a diferencia de sistemas genéricos que pueden ser complejos o costosos.

Reducción de errores en pagos y asignaciones.

Mejor clima laboral al aumentar la confianza en los procesos.

Metodología
En el desarrollo del proyecto ROSALOPZManager, utilizaremos la metodología XP (Extreme Programming), ya que se enfoca en la entrega continua de software funcional, fomentando la colaboración constante con los usuarios y la mejora iterativa. Esta metodología es ideal para proyectos como este, donde la calidad del código, la adaptabilidad y la respuesta rápida a los cambios son esenciales. XP nos permitirá garantizar un desarrollo eficiente mediante prácticas clave como la programación en parejas, pruebas continuas, refactorización y retroalimentación frecuente, asegurando que cada entrega cumpla con las expectativas del cliente.

Fase 2 - Diseño
Objetivo de la Fase 2
Definir la estructura lógica, visual y funcional del sistema completo ROSALOPZManager, que incluirá las funcionalidades de registro, login, inicio, perfil de usuario, nómina, gestión de inventarios, tareas y reportes. Este diseño servirá como la base para las siguientes fases de desarrollo.
Diseño de la Base de Datos
La base de datos será desarrollada en PostgreSQL, organizada para manejar eficientemente la información de usuarios, nóminas, inventarios, tareas y reportes.
Tablas Principales
Tabla: Usuarios
Descripción: Almacena los datos de los usuarios registrados.
Campos:
id_usuario (int): Identificador único.
nombre (varchar): Nombre del usuario.
email (varchar): Correo electrónico único.
contraseña (varchar): Contraseña encriptada.
rol (varchar): Rol del usuario (administrador, jefe, empleado).
Tabla: Nóminas
Descripción: Almacena los registros salariales de los empleados.
Campos:
id_nomina (int): Identificador único.
usuario_id (int): Relación con la tabla usuarios.
salario (double presicion): Salario base.
deducciones (double presicion): Descuentos aplicados.
bonificaciones (double presicion): Bonos adicionales.
fecha (date): Fecha del cálculo de la nómina.
Tabla: Inventarios
Descripción: Almacena el control de materiales y productos.
Campos:
id_producto (int): Identificador único del producto.
nombre (varchar): Nombre del producto.
cantidad (int): Cantidad disponible.
proveedor (varchar): Nombre del proveedor.
fecha_actualizacion (date): Última actualización del inventario.
Tabla: Tareas
Descripción: Almacena las tareas asignadas a los empleados.
Campos:
id_tarea (int): Identificador único.
descripcion (varchar): Descripción de la tarea.
usuario_id (int): Relación con el empleado asignado.
estado (varchar): Estado de la tarea (pendiente, en progreso, completada).
fecha_vencimiento (date): Fecha límite.
Tabla: Reportes
Descripción: Almacena los datos generados de los reportes.
Campos:
id_reporte (int): Identificador único.
tipo (varchar): Tipo de reporte (nómina, inventarios, tareas).
contenido (json): Datos del reporte en formato JSON.
fecha_generacion (date): Fecha de creación del reporte.
Relaciones Clave:
Usuarios ↔ Nóminas: Relación uno a muchos.
Usuarios ↔ Tareas: Relación uno a muchos.
Usuarios ↔ Reportes: Relación uno a muchos.
Inventarios: Independiente, pero relacionado con reportes.

Diseño de Diagramas
Diagrama de Casos de Uso
Descripción General: El Diagrama de Casos de Uso representa las interacciones entre los actores del sistema y las funcionalidades que ofrece la aplicación. En este caso, el sistema ROSALOPZManager está diseñado para automatizar procesos clave en una fábrica, como la gestión de nóminas, inventarios, tareas, reportes y seguridad. Los actores involucrados incluyen Administrador, Jefe y Empleado, y los casos de uso cubren funcionalidades como el cálculo de nóminas, la gestión de inventarios, la asignación de tareas, la creación de reportes, y el acceso a la información de usuarios.
Actores:
Administrador: Persona encargada de gestionar el sistema, con permisos para administrar usuarios, generar reportes, gestionar nóminas, inventarios y tareas.
Jefe: Persona responsable de asignar tareas a los empleados y generar reportes de desempeño.
Empleado: Persona que consulta su historial de pagos, tareas asignadas y actualiza su información personal.
Relaciones:
Include: Representa un caso de uso que siempre se ejecuta como parte de otro caso de uso. Ejemplo: "Calcular Nómina" incluye "Generar Reporte de Nómina".
Extend: Representa un caso de uso opcional que se ejecuta solo cuando se cumple una condición. Ejemplo: "Generar Reporte de Inventarios" puede extenderse para "Generar Reporte PDF".
Diagrama de Entidad-Relación (ER)
Descripción General: El Diagrama de Entidad-Relación (ER) describe cómo se estructuran y se relacionan las entidades dentro de la base de datos del sistema. A través de este diagrama, se visualizan las entidades principales, como Usuarios, Inventarios, Nóminas, Reportes y Tareas, y cómo estas se conectan entre sí mediante relaciones uno a muchos.
Entidades:
Usuarios: Almacena la información de los usuarios del sistema (empleados, jefes, administradores), como su nombre, correo electrónico, contraseña y rol.
Inventarios: Contiene información sobre los productos y materiales en inventario, como nombre, cantidad, proveedor y fecha de actualización.
Nóminas: Almacena los detalles de los sueldos, deducciones y bonificaciones de cada usuario, junto con la fecha de cálculo.
Reportes: Registra los reportes generados por el sistema, incluyendo el tipo de reporte, contenido y fecha de generación.
Tareas: Contiene las tareas asignadas a los usuarios, con descripciones, fechas de vencimiento y estado de cumplimiento.
Relaciones:
Usuarios a Inventarios: Un usuario puede gestionar muchos productos, pero cada producto solo tiene un usuario responsable.
Usuarios a Nóminas: Un usuario tiene muchas nóminas asociadas a lo largo del tiempo.
Usuarios a Reportes: Un usuario puede generar muchos reportes, pero cada reporte tiene un solo usuario que lo genera.
Usuarios a Tareas: Un usuario puede tener múltiples tareas asignadas.
Diagrama de Componentes
Descripción General: El Diagrama de Componentes muestra la arquitectura modular del sistema ROSALOPZManager, dividiendo la solución en partes independientes que interactúan entre sí. Los componentes principales incluyen la Interfaz de Usuario (UI), el Backend (Controladores y Lógica de Negocio) y la Base de Datos, cada uno con un rol específico en el procesamiento de datos y la interacción del usuario.
Componentes:
Interfaz de Usuario (UI): Es la capa responsable de interactuar con el usuario. Proporciona interfaces gráficas para que el usuario ingrese datos, consulte información y realice acciones como consultar nóminas, tareas y productos en inventario.
Backend (Controladores y Lógica de Negocio): La lógica de negocio procesa las solicitudes del usuario y realiza cálculos como el cálculo de nóminas, la asignación de tareas y la gestión de inventarios. Este componente también maneja las interacciones entre la UI y la base de datos.
Base de Datos: Almacena la información relevante del sistema, como los datos de los usuarios, inventarios, tareas, nóminas y reportes. Permite la persistencia de los datos y facilita la consulta y actualización de la información.
Relaciones entre Componentes:
Interfaz de Usuario (UI) a Backend: La UI envía solicitudes al Backend para ejecutar operaciones como generar reportes, asignar tareas y consultar inventarios.
Backend a Base de Datos: El Backend consulta y actualiza la Base de Datos para gestionar la información de los usuarios, tareas, inventarios, nóminas y reportes.
Interfaz de Usuario (UI) a Base de Datos: A través de la lógica de negocio, la UI interactúa indirectamente con la Base de Datos para obtener y mostrar los datos al usuario.
Diagrama de arquitectura
El diagrama de Arquitectura (Componentes) describe cómo está estructurado el sistema ROSALOPZManager en términos de sus módulos principales y sus interacciones. Este diagrama utiliza una representación modular para destacar las responsabilidades y conexiones de cada componente. Vamos a analizarlo:
Componentes principales:
UI (Interfaz de Usuario):
Función: Es la capa que interactúa directamente con los usuarios finales (jefes, administradores, empleados).
Tecnologías utilizadas: HTML, CSS, JavaScript, Bootstrap (para diseño responsivo).
Características:
Formulario de login y registro.
Pantallas para visualizar y gestionar nóminas, inventarios, tareas y reportes.
Gráficos y tablas que muestran datos procesados.
Interacción: Envía solicitudes al backend mediante una API REST (normalmente usando HTTP/HTTPS).
Backend:
Función: Es el núcleo de la lógica del sistema. Se encarga de procesar las solicitudes recibidas desde la UI, realizar cálculos o validaciones y gestionar los datos que interactúan con la base de datos.
Tecnologías utilizadas: Node.js con el framework Express.js.
Características:
Implementa la arquitectura Modelo-Vista-Controlador (MVC):
Modelo: Gestiona las reglas de negocio y las interacciones con la base de datos.
Controladores: Procesan solicitudes y ejecutan la lógica del negocio.
Vistas: Devuelven las respuestas adecuadas a la UI.
Maneja rutas específicas para operaciones como consulta de nóminas, inventarios y reportes.
Interacción: Comunica la UI con la base de datos y asegura que las solicitudes y respuestas fluyan correctamente.
Base de Datos (Database):
Función: Almacena de manera persistente toda la información crítica del sistema, como usuarios, nóminas, inventarios, tareas y reportes.
Tecnologías utilizadas: PostgreSQL.
Características:
Tablas principales incluyen:
Usuarios: Datos de los empleados, administradores y jefes.
Nóminas: Sueldos, deducciones y bonificaciones.
Inventarios: Información sobre materiales y stock.
Tareas: Actividades asignadas con fechas y estados.
Reportes: Información resumida para análisis y decisiones.
Consultas SQL optimizadas para manejar datos en tiempo real.
Interacciones:
UI → Backend:
Cuando un usuario realiza una acción (ejemplo: consultar nóminas), la UI envía una solicitud HTTP/HTTPS al backend a través de una API REST.
La UI no interactúa directamente con la base de datos, lo que asegura que la lógica del negocio y la seguridad sean gestionadas por el backend.
Backend → Database:
El backend ejecuta consultas SQL para insertar, actualizar, eliminar o recuperar datos de la base de datos según las solicitudes recibidas.
Esta separación asegura que los datos estén protegidos y procesados adecuadamente antes de ser enviados a la UI.
Beneficios de esta arquitectura:
Separación de responsabilidades:
Cada componente tiene un rol específico, lo que facilita el desarrollo, mantenimiento y escalabilidad.
Escalabilidad:
La base de datos y el backend pueden ampliarse para manejar más usuarios o datos sin afectar directamente a la UI.
Modularidad:
La UI, el backend y la base de datos pueden evolucionar o actualizarse de manera independiente siempre que mantengan sus interfaces.
Seguridad:
La UI nunca interactúa directamente con la base de datos, evitando riesgos de seguridad (por ejemplo, ataques SQL Injection).
Diagrama de secuencia
Describe el flujo de interacción entre los actores (usuarios) y los componentes del sistema ROSALOPZManager, enfocándose en el proceso de asignación de tareas. Este tipo de diagrama es útil para visualizar el orden en que ocurren las acciones y cómo se comunican los elementos del sistema. Vamos a analizarlo en detalle:
Elementos principales del diagrama:
Actor (Jefe):
Representa al usuario que interactúa con el sistema.
En este caso, el jefe es quien utiliza el sistema para gestionar las tareas de los empleados.
UI (Interfaz de Usuario):
Es la parte del sistema con la que interactúa directamente el jefe. Aquí el usuario puede:
Consultar tareas existentes.
Asignar nuevas tareas.
Está diseñada con tecnologías como HTML, CSS y JavaScript.
Backend:
Procesa las solicitudes enviadas desde la UI.
Implementa la lógica del negocio (en este caso, para la gestión de tareas) y maneja las interacciones con la base de datos.
DB (Base de Datos):
Almacena de manera persistente toda la información del sistema, incluyendo las tareas asignadas.
Responde a las solicitudes de lectura o escritura realizadas por el backend.
Flujo de interacción:
1. Consulta de tareas existentes:
El jefe accede al módulo de tareas desde la UI:Envía una solicitud para ver las tareas asignadas a través de la interfaz de usuario.
La UI envía la solicitud al backend:Aquí, el backend recibe la solicitud y procesa la información requerida.
El backend consulta las tareas en la base de datos:Se ejecuta una consulta SQL en la base de datos para recuperar las tareas almacenadas.
La base de datos devuelve la información al backend:El backend recibe las tareas encontradas.
El backend envía los datos a la UI:Los datos se procesan y se muestran al jefe en un formato comprensible (ejemplo: tabla o lista de tareas).
2. Asignación de nueva tarea:
El jefe asigna una nueva tarea desde la UI:Ingresa la descripción, el empleado asignado y la fecha de vencimiento.
La UI envía la solicitud al backend:La solicitud incluye los datos ingresados por el jefe.
El backend procesa la solicitud y actualiza la base de datos:Se ejecuta una operación de inserción en la tabla de tareas para guardar la nueva tarea.
La base de datos confirma la operación:Devuelve un mensaje de éxito al backend (por ejemplo, "Tarea registrada exitosamente").
El backend envía una confirmación a la UI:La interfaz muestra un mensaje de éxito al jefe, indicando que la tarea fue asignada correctamente.
Propósito del diagrama:
Visualizar el flujo de trabajo: Muestra cómo las tareas fluyen desde el jefe hasta el sistema y viceversa.
Asegurar la consistencia: Define un flujo claro para evitar problemas en el diseño y la implementación del sistema.
Fomentar la comunicación: Ayuda a los desarrolladores y usuarios a entender cómo interactúan las distintas partes del sistema.
Resumen de las interacciones:
El jefe inicia las solicitudes desde la UI.
La UI comunica esas solicitudes al backend, quien las interpreta y procesa.
El backend realiza operaciones de consulta o actualización en la base de datos.
Los resultados de la base de datos se devuelven al backend, y este a su vez, los entrega a la UI para su visualización o confirmación.
